## Iteration 702: idea 11 begun - three shared stretches factored on cold paths

dup-scan.py's pairs on paths the benchmarks never take, first: fg and bg
began alike - the job pruned, named, its errors - and both sent SIGCONT
and marked the job running: JOB-SELECT ( --- f ) and JOB-CONT. ulimit's
report and its setting both read the limits and failed the same way:
UL-GET ( --- soft hard -1 | 0 ). Built in a worktree, so the verify of
701 ran undisturbed: the CV8 image 127,228 -> 127,196 bytes, the native
code 394,075 -> 393,915. bg, fg, an unknown job, ulimit read and set -
right; the shell suite on all four shells, the differential suite: pass.

A fourth, the prompt's \w and \W reading PWD alike (PD-PWD), was built
and taken out: the CV8 image came out 8 bytes larger - a header and two
calls weigh more there than the eight words they replace - though the
native code was 16 smaller. The condition is both images no larger. So
idea 11's factoring pays natively - a copy of a dozen words is 150-300
bytes of machine code - and barely or not at all in CV8's bytecode,
where it is 15-25: a pair is worth factoring only where the run is long
or repeated more than twice.
Baseline: the seven CV8 size and image-sum rows, 32 bytes smaller each;
the native rows unchanged - its file grows and shrinks by whole pages.
