## Iteration 704: the deferred push - priced, built, fired 4 times, set aside

The user chose it from 702's options. Priced first, from relfsh-native's
disassembly: 10,611 pushes; 803 whose cell is read straight back with
only register code between - 366 in the kernel's cross-compiled words,
437 in the shell's - and 3,089 by a first, looser count whose loop ran
through objdump's continuation lines. The kernel's share is the cross
compiler's: it folds nothing, so SKIP-BRANCH ends `push; mov ebx,3; add
rbx,[r15]; add r15,8`, and # tests `push; push; mov ebx,9; mov
rax,[r15]; add r15,8; cmp; setg`.

Built in kernel-native.4 for the shell's words: PUSH, (and an inline
DUP) records where it laid the push; at +, -, AND, OR, XOR, after the
existing folds, DEFER-OK? walks the bytes from that push to here with
SAFE-LEN - the encodings of loads into rbx and operations on rbx alone,
none touching rcx, r15 or rsp, none relative - and if all pass and no
jump has landed, the push becomes mov rcx,rbx, the code after it moves
back 4 bytes and the operation takes rcx. Checking the bytes rather than
tracking every emitter made it safe against the folds that unlay code.
Right on what it was tried on - sums, differences, I CELLS + in a loop,
masks. Then the shell: 4 deferrals in all (45 mov rcx,rbx where there
were 41), its code 394,075 -> 398,971. The folds of 628-669 had taken
the literal, variable, OVER and pair cases already; what is left ends
mostly in a compare, a store or a branch. And the new words, compiled by
the native compiler, were 4.9 KB of kernel: SAFE-LEN 2,566, DEFER-OP?
1,435. Set aside; kernel-native.4 restored, the shells 703's byte for
byte. NATIVE.md 14 has it, and where the pricing points: the kernel's
own code, which the cross compiler could fold at no cost in the image.

## Iteration 705: the kernel's own code folded, by the cross compiler

704's pricing found 366 of the read-back pushes in the kernel's words,
209 of them a literal and the operation after it: the cross compiler,
which lays the kernel's code from native.4's templates, folded nothing.
Now it folds as the run-time compiler has since 628 and 645: N-LIT
records where the literal began and ended and its value; N-FOLD? - the
literal laid last, no jump landed since, an imm32 - rewinds THERE to
undo it; +, -, AND, OR and XOR then lay op rbx,imm; =, <>, <, > and U<
lay cmp rbx,imm and their setcc (N-CMP?); !, C! and +! to a literal
address lay one store to it and pop. Landings set N-BARRIER: N-RESOLVE,
BEGIN, DO and ?DO.

The first build stopped at `Undefined word N-CMP?`: defined among the
templates, after CURRENT had become NPRIMS, where the templates'
compilation does not look - moved up beside N-CMP. Then: the kernel's
code 59,667 -> 54,540 (-5,127 - more than the 209 pairs: stores to
variables and comparisons with literals are everywhere in kernel.4); the
shell's code -5,288, the file 416,104 -> 407,912. The self-build the
same, every native test, the suites, the milestone programs as before.
Over layouts against 704, 13 rounds: 1.007, 1.007, 0.998, 1.013, 1.001.
